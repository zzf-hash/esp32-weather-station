# 设计规范：方向二「暖色渐变卡片」

本规范和 `code/main.py`、`code/ui.py` 一一对应，所有坐标都取自实际代码。屏幕为竖屏 240×320，RGB565，MADCTL 0x48。

## 0. 通用约定
- **文字坐标**：x 是字形左边。y 是本档「墨迹带」的顶边：makefont 已经裁掉了每档字号所有字形共有的上下空白，所以 y 基本就是字的视觉顶边。
- **各档带高**：96→73、64→49、56→43、24→25、18→20、16→17（px）。
- **字间距**：`aa_text` 字间距固定 2px。宽 = `ui.aa_width(文本, 字号)`，下表的宽都是按示例文本实测的。
- **字体**：Noto Sans CJK SC（SIL OFL，可免费商用）。Bold 用于 96/64/56/24，Regular 用于 18/16。
- **页码**：`page_dots`，y=302。当前页是 22×8 胶囊，其他页是半径 3 的圆点，起点 x=96，间距 18。颜色取 SKY 表第三列。
- **数据源不变**：NTP 时间、Open-Meteo（temp、humi、code、tmax、tmin）、AHT20（temp、humi）、config.CITY_NAME。另有两项由已有数据推导：「时段」按小时划分，「舒适度」按湿度阈值判定。

## 3. 图标画法
只用 framebuf 的 `ellipse(..., True)`、`line`、`fill_rect`，不用位图。坐标以左下角 (x, y) 为基准，大图标宽约 74px。
- **太阳**：中心 (cx, cy)，实心圆半径 r。8 条光芒从半径 r+5 画到 r+11，每条用 3 根相邻 1px 线拼成 3px 粗。大图标 r=16–20，小图标 r=7–10。
- **月亮**：MOON 色实心圆半径 r，再用背景色在 (cx+r/2, cy−r/3) 画半径 r−2 的圆，挖出月牙。背景色要先 `fb.pixel()` 取当前位置的色带色。
- **云**：3 个圆 (x+22, y−16, r16)、(x+44, y−22, r20)、(x+62, y−12, r12)，加一块圆角底 (x+6, y−14, 68×14, r7)。小图标所有尺寸 //2。
- **多云**：先在 (x+54, y−44) 画 r16 的太阳，再在上面盖云。
- **雨**：云整体上移 12px，下方画 4 根 3px 粗斜线，横向间距 14，每根 (xx, y+6)→(xx−6, y+18)，颜色 RAIN。
- **雪**：云上移 12px，下方 4 个半径 3 的白色圆点，交错排列。
- **雾**：3 条圆角横条，高 6、圆角 3，宽 64/58/52，竖向间距 12。
- **雷**：灰云 CLOUD_D 加一道 4px 粗的 Z 字折线，颜色 BOLT。
- **小图标**（时钟页卡片，白底）：云改用 CLOUD_D；雨 3 根短线、雪 3 个点；月亮挖月牙用 CARD 色。

## 5. 字库子集策略
| 字号 | 字重 | 字符集 | 字形数 |
|---|---|---|---|
| 96 | Bold | 0-9 - | 11 |
| 64 | Bold | 0-9 : | 11 |
| 56 | Bold | 0-9 . - | 12 |
| 24 | Bold | ASCII 标签 + 中文清单 | 85 |
| 18 | Regular | ASCII 标签 + 中文清单 + A–Z、a–z | 136 |
| 16 | Regular | ASCII 标签 + 中文清单 | 85 |

- **大字号只放数字和符号，绝不放汉字。**
- 生成后再裁掉每档共有的上下空白行（Noto 行高很松，96px 档原始高度 140，裁后 73）。
- 生成的 `font.py` 是 349 KB 的 Python 源码，其中字形原始数据约 91 KB。
- 字库里缺的字，`aa_text` 会直接跳过，不会崩溃。所以改了文案而忘了重新生成字库时，表现是屏上「少字」。
- 生成命令（PC 上运行）：

```
FONT_BOLD=…/NotoSansCJK-Bold.ttc FONT_BOLD_INDEX=2 FONT_REGULAR=…/NotoSansCJK-Regular.ttc FONT_REGULAR_INDEX=2 python makefont.py
```

  Windows 上如果装的是单独的 `NotoSansCJKsc-*.otf`，index 用 0（这是默认值）。

## 6. 使用禁忌
- 不做动画、滚动、秒级刷新（不显示秒，不做闪烁冒号）。签名机制保证内容不变时不重绘。
- 背景只用 10 条色带，不要逐行插值渐变，也不要做抖动：RGB565 低饱和过渡会出现不规则色带，而且逐像素计算太慢。
- 不用位图图标或照片；图标只用 ellipse、line、fill_rect。
- 大字号里不放汉字；同一个字号只能有一种字重（GLYPHS 以字号为键）。
- 白字只放在色带上，卡片上用 INK/SUB；不要把白字放在 snow、home 这类浅色带的下半部分。
- 不加新的数据源字段，比如体感温度、AQI、未来几天预报。要加需要先改 `fetch_weather`，这不属于本次范围。
- 不写英文装饰字。城市名如果是拼音，只能用 18px 显示。

## 7. 校色（colortest.py）
运行：`mpremote connect COM7 cp ili9341.py config.py :/ + run colortest.py`。这只是临时运行，不覆盖 main.py。然后对照 `colortest_expected.png` 看：
1. **RED 块显示成蓝色、BLUE 块显示成红色，GREEN 正常**：红蓝通道顺序反了。在 colortest.py 里设 `MADCTL = 0x40` 再运行，确认正常后，把 `ili9341.py` 的 `_INIT` 里 `(0x36, b'\x48', 0)` 改成 `b'\x40'`。如果画面同时出现左右镜像，就改 MX 位：0x48 ↔ 0x08，或 0x40 ↔ 0x00。
2. **颜色发花**（纯红偏绿或变暗、白色正常、暮色色带台阶乱跳）：RGB565 高低字节顺序反了。framebuf 按小端存储，`show()` 原样推送，而 ILI9341 默认先收高字节。设 `SWAP_BYTES = True` 再运行一次，如果变正常就确认是这个问题。永久修法按优先级：
   a. 在 `_INIT` 末尾加 `(0xF6, b'\x01\x00\x20', 0)`，即 Interface Control 的 ENDIAN 位改为低字节在前。零开销，但部分国产兼容屏不支持。
   b. 不行的话，在 `ui.rgb565` 返回字节交换后的值，同时 `_expand` 和 `aa_text` 里读回像素的地方先做字节交换再解码。零运行开销，但要改 3 处。
   c. 不要在 `show()` 里用 Python 循环交换 153600 字节，太慢。
3. **WHITE 偏黄或偏蓝、CARD 和 WHITE 分不清**：属于屏本身的色温，不是代码问题。可以把 CARD 调深一点，比如 rgb565(250,238,222)。
4. **两项都不对**：先按第 2 条修字节序，再看红蓝。
